### What changed between v1 and v2
| v1 problem | v2 fix | Result |
|---|---|---|
| Bare topic queries got cards ("pronunciation", "english speaking", "accent kaise improve kare") | Rule: a topic name or a "how to / kaise improve" question is advice, so `none` | 5 → 0 ambiguous cards |
| Mother-tongue-influence requests went to spoken_english | Pronunciation label now names accent / MTI; MTI few-shot example | Both rows correct |
| "Interviewer ban jao aur DBMS pe questions poocho" went to viva_revision | "Be my interviewer" counts as mock_interview even for subject questions | Correct |
| Confidence was almost always 0.92 or 0.95, so thresholds couldn't separate good from bad | Asked for the full 0–1 range, with calibrated few-shot confidences | Still narrow (0.94–0.98); see finding 2 |
| Threshold grid jumped from 0.95 to 0.99, which switched viva off | Sweep also tries every confidence the model produced | viva threshold 0.96 → recall 100% → 96.7% |

### Classifier time limit: 1.5 s → 2 s (decided 2026-11-16)
| Limit | Timeouts on the primary model | Effect |
|---|---|---|
| 1.5 s (v1 run) | 22/159 (14%) | Those learners get no card |
| **2 s (v2 run)** | **9/159 (5.7%)** | 26 calls in the v2 run took >1.5 s and would have been lost at the old limit |

Most of the latency is Groq **free-tier queueing** (~0.3–0.4 s per call), not model time.

## Findings and risks
1. **Small synthetic data flatters the scores.** 100% precision on 200 rows I wrote doesn't mean 100% on real learners, who make typos, use slang and send half-formed requests. The thresholds (especially viva 0.96) are fitted to very few hard cases. Also, two v2 few-shot examples are close *in meaning* (not wording) to ambiguous-set items: "How to sound confident in a group discussion?" vs "how to speak confidently", and "Public speaking" vs bare topic names. That may flatter the 0-ambiguous-cards result. **Re-run `npm run eval:classifier -- --write-thresholds` once real labelled data exists, and judge v2 on rows written by other people.**
2. **The model's confidence carries little information.** gpt-oss-20b scores almost every practice request 0.95–0.97. Precision comes from the *label*, and the thresholds mostly act as a backstop. A threshold like 0.96 is fragile: a small model or prompt change shifts it. The CI gate forces a re-eval on any such change.
3. **Free-tier capacity can't serve real traffic.** Each classification uses ~650–750 tokens, and the key allows **8,000 tokens/minute shared with chat**. That's roughly 10 classifications a minute, with no chat. Dogfood (Phase 8) needs a paid Groq tier (architecture §17 #14); the prefilter roughly halves classifier calls.
4. **Fallback is a bit weaker** (recall 95%): it misses "help me get fluent in English before my college presentations"-style requests. It's acceptable as a fallback because it never shows a wrong card.

## How to use
```bash
npm run eval:check                                # CI gate, offline, re-scores cached predictions
npm run eval:classifier                           # live eval, both models (~15 min per model on the free tier; resumable)
npm run eval:classifier -- --write-thresholds     # also re-tune thresholds (P2.6)
npm run eval:classifier -- --report-only          # rebuild eval-report.md from the cache
```
Changing the prompt? Bump `CLASSIFIER_PROMPT_VERSION`, run the live eval, commit `data/intent-eval/results/*` plus the report. CI won't pass otherwise. Archived v1 predictions live in `data/intent-eval/results/archive/`.

Try one message (admin):
```bash
curl -X POST -b "svs_session=<cookie>" -H 'content-type: application/json' \
  -d '{"text":"Kal mera Infosys interview hai, mock interview le lo"}' http://127.0.0.1:8787/v1/admin/classify
```
